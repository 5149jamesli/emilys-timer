# Emily's Timer

A simple interval timer web app. The user sets up repeating work and rest intervals (for example 10 sets of 1 minute work with 30 seconds rest), starts it, and hears a tone at every phase change. They can pick which tone plays.

## Stack

- Vite + TypeScript (strict), vanilla DOM: no UI framework. Keep it that way unless the UI grows enough to need one.
- Vitest for unit tests.
- Tones are synthesized with the Web Audio API, so there are no audio files.
- Fonts are bundled from npm via `@fontsource` (Cormorant Garamond, Jost), so there are no external font requests.
- No backend and no persistence yet.
- It's an installable web app (PWA): a manifest, iPhone home-screen tags and an offline service worker.
- It's hosted on GitHub Pages and deployed by `.github/workflows/deploy.yml` on every push to `main`.

## Commands

```bash
npm run dev        # dev server at http://localhost:5173 (honors $PORT, see vite.config.ts)
npm test           # unit tests (vitest run)
npm run typecheck  # tsc --noEmit
npm run build      # typecheck + production build into dist/ (also emits sw.js)
npm run preview    # serve the production build (the only way to test offline/PWA)
node scripts/make-icons.mjs   # regenerate the app icons in public/
```

Run `npm test` and `npm run typecheck` before calling a change done.

## Layout

- `index.html`: page markup: the dial (SVG ring with phase, clock and set count), the Start/Pause and Reset buttons, then the setup form (sets, work sec, rest sec, tone, Listen, volume slider).
- `src/timer.ts`: pure timer logic, with no DOM, audio or clock access:
  - `buildSchedule(config)` expands a config into an ordered `Phase[]`.
  - `positionAt(schedule, elapsedMs)` says which phase you're in and how much time is left.
  - `formatClock(ms)` formats the display.
- `src/tones.ts`: the `TONES` registry plus `playTone(id, repeat)`, `unlockAudio()` and `setVolume(0–1)`. There are five tones, ordered from most jarring to most soothing: Alarm clock, Digital beep, Doorbell chime, Wind chimes, Temple bell (the default).
- `src/main.ts`: UI wiring and the run state machine (`idle → running ⇄ paused → done`).
- `src/style.css`: styling. The body gets `data-state="idle|running|paused|done"` and `data-phase="work|rest"`, and the CSS keys off those.
- `src/timer.test.ts`: tests for the timer logic.
- `src/service-worker.js`: offline service worker *template*. The `serviceWorker()` plugin in `vite.config.ts` fills in the precache list and the cache version at build time and emits `dist/sw.js`. `main.ts` registers it in production builds only.
- `public/`: copied as-is into the build: `manifest.webmanifest`, `favicon.svg`, `icons/*.png`. The icons are generated by `scripts/make-icons.mjs`, so edit the script, not the PNGs.
- `vite.config.ts`: `base: './'` (relative URLs, so the build works under GitHub Pages' `/<repo>/` sub-path), the `PORT` env override and the service-worker plugin.

## Behavior rules

- **Schedule shape:** each set has one work phase. A rest phase follows every set except the last. When rest is 0, no rest phases are created.
- **Tones:** one tone plays on Start, one at each phase change, and the same tone plays 3 times when the workout finishes. Repeats are spaced by each tone's `length`.
- **Timing is timestamp-based:** elapsed time = time accumulated before the current run + (`performance.now()` - start of current run). The display is computed from that on every animation frame. Never count down by decrementing on a `setInterval`, because that drifts and breaks when a background tab gets throttled.
- **Volume:** every note goes through one master `GainNode` in `tones.ts`.
  - The slider runs 0–100%, and gain = (slider)², so it feels even. 100% is each tone's designed loudness, and 0 shows "Off".
  - The slider stays usable mid-workout (`syncControls` only locks the number inputs). Letting go of it plays the current tone.
  - The level is saved in `localStorage` (`emilys-timer.volume`), which is a per-device convenience.
  - On iPhone it sits on top of the phone's own volume buttons.
- **Audio must be unlocked by a user gesture.** `unlockAudio()` is called from the Start click (and Preview). Don't create the `AudioContext` at module load.
- **Screen Wake Lock** keeps the screen on while running. It's best effort and failures are ignored.

## iPhone / PWA

The main way people use this is on iPhone via Safari → Share → **Add to Home Screen**.

- **Home screen:** `index.html` has `apple-touch-icon`, `apple-mobile-web-app-title` and `apple-mobile-web-app-capable`, plus the manifest (`display: standalone`), so it launches full-screen with its own icon and name.
- **Offline:** the service worker precaches the app shell, including only the Latin `.woff2` fonts.
  - Page loads are network-first, so a new deploy appears the next time the app is opened. Everything else is cache-first.
  - Cache lookups use `ignoreVary: true`. Without it, the cached JS/CSS didn't match offline.
  - If you add a file the app needs offline, check that it ends up in the precache list.
- **Audio over a podcast:** `AUDIO_SESSION_TYPE` in `tones.ts` sets `navigator.audioSession.type = 'transient'` so tones play over another app's audio, briefly ducking it, instead of pausing it.
  - The trade-off: the tones likely follow the ring/silent switch.
  - `'playback'` would ignore the silent switch but stops the podcast. Don't switch to it without asking.
  - This hasn't been tested on a real iPhone yet.
- **Interruptions:** iPhone can leave the `AudioContext` `suspended` or `interrupted` after calls or app switches. `unlockAudio()` and a `visibilitychange` listener resume it.
- **Background:** iPhone pauses web apps that aren't on screen, so tones only play while Emily's Timer is the app on screen. Wake Lock keeps the screen on during a workout. A real fix would need a native app.

## Design direction: calm spa

The app should feel like a spa: calm, warm, unhurried. Keep new UI in this style.

- **Palette** (tokens on `:root` in `style.css`): warm sand background, stone-colored text, sage green for rest and the main accent, soft clay for work. Work should feel warm, never alarm-red. Dark mode redefines the same tokens as a deep moss-charcoal "dim treatment room".
- **Type:** Cormorant Garamond (light serif) for the clock and the italic title, Jost (light geometric sans) for everything else. Labels are small, uppercase and widely letter-spaced.
- **Shapes:** pill-shaped buttons, softly rounded inputs on a sand surface, no hard borders, plenty of space.
- **Motion:** slow and soft. Colors fade between phases (~1–2s), a glow behind the dial "breathes" on an 8s cycle while running, and the ring drains smoothly. `prefers-reduced-motion` turns all of this off.
- **Focus:** while a workout runs, the settings fade back so the dial is the focus.
- Use colors only through the tokens, and don't hardcode new colors in rules.

## Conventions

- Put new timer math in `timer.ts` as pure functions and test it there. Keep `main.ts` thin.
- To add a tone, add an entry to `TONES` in `src/tones.ts` with a unique `id`, a `label`, a `length` in seconds and a `play(ctx, at)` function. Put it in the jarring-to-soothing order. The dropdown picks it up automatically.
- Read form values from the inputs, not `FormData`, because the inputs are disabled mid-run and `FormData` skips disabled fields.
- Durations are in milliseconds internally. The form uses seconds.

## Known limitations / ideas

- Tones don't play while the app is in the background or the phone is locked (see iPhone / PWA above). The clock is still correct when you come back.
- Not built yet:
  - saving presets and the last-used settings (localStorage)
  - separate tones for work start, rest start and finish
  - a 3-2-1 countdown beep
  - a warm-up or cool-down phase
